The Windows app

The same viewer, plus what a browser cannot do. Free, and it keeps itself up to date.

  • Read aloud and narrated video — the voice runs on your PC; the model is a one-time 383 MB download you are asked about first.
  • Double-click to open PDF, HWP/HWPX, Word, PowerPoint, Excel, CSV, mail, Markdown and images; recent documents on the start screen.
  • Batch converters on your PATH — topdf, hwp2pdf, hwp2hwpx, hwpx2hwp: files, wildcards or whole folders.
  • Huge PDFs — over 500 MB (up to about 2 GB) are read in pieces, so they open in seconds.
  • An MCP server for AI agents such as Claude — read any of these formats and convert them to PDF, no Node.js needed.
  • Automatic updates — downloaded in the background, checked against the published hash, installed when you restart.
Installer (recommended) WZ_Reader_Setup_<version>.exe Shortcuts, file associations, the console converters and automatic updates. Portable WZ_Reader_<version>.exe One file, no install. Unpacks itself on every start (~5 s) and does not update itself.

Add it to your site

One <iframe> is all it takes. Put your document's URL (encoded) in url.

urlthe document to display — PDF, HWP, Word, PowerPoint, Excel, Markdown, mail or an image (encode with encodeURIComponent) filealias for url embed=1hide the editing chrome (read-only). Omit it to open the full viewer. langen or ko to force the interface language (otherwise it follows the browser)
⚠️ CORS note: the web build fetches the document in the browser, so its host must allow cross-origin access. The safest setup is to serve the viewer and the document from the same domain — upload the npm run build output (dist/) to your site and keep the document on the same origin. The desktop app is not affected by CORS.

Private mode — only the documents you designate

embed=1 only hides buttons: anyone can edit the address and open something else. For a viewer that shows just the documents your server chose, view only, host the web build yourself and place a private.json next to app.html. Every build carries a working example there — private.example.json — to copy to that name.

{
  "documents": {
    "rfp":    "docs/RFP-2026.pdf",
    "notice": { "url": "/files/get?id=17", "name": "notice.hwp" }
  },
  "print": false
}
<iframe src="https://your-site/viewer/app.html?doc=rfp"
  style="width:100%; height:80vh; border:0;" allowfullscreen></iframe>
docwhich designated document to show (may be left out when there is only one) documentsid → URL, or { url, name } when the URL has no file name. Paths are resolved against private.json. printtrue to allow printing (off by default — printing is also "save as PDF")
  • Works: zoom, fit, rotation, page list, two-page and grid views, fullscreen, find, OCR.
  • Switched off: opening any other document (file, drop, ?url=, mail attachment), editing, saving, downloading — and their keyboard shortcuts.
  • It belongs to the deployment, not the link — there is no URL switch to remove. A private.json that exists but cannot be read keeps the viewer closed.
  • When you redeploy, leave private.json on the server — a script that clears the folder first must skip it.
🔐 Not access control: the browser downloads the document to show it. Who may see a document at all is your server's decision (sign-in); private mode keeps the viewer from being a way to open, change or save anything else.
